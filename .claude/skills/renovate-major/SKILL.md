# renovate-major

Renovate の major 更新 PR を，この repo のレイヤー構成 (Terraform / Ansible / k8s / Tailscale) に照らして検証し，merge 可否を判定する．

**main への merge は Ansible 以外すべて本番デプロイ**になる (Terraform apply，ACL apply，ArgoCD sync)．CI が通っても即 merge 可とは判断しない．**自動 merge は行わない**．最終判断はユーザーが行う．

## 引数

`[PR番号]`．省略時は次で major 候補を列挙し，対象をユーザーに選んでもらう．

```sh
gh pr list --author "app/renovate" --state open --json number,title,headRefName,labels
```

title / branch (`renovate/<dep>-<N>.x`) / label から major を判定する．minor・patch は対象外として報告する．

## 手順

### 1. 取得と分類

```sh
gh pr view <N> --json title,body,headRefName,files,statusCheckRollup
gh pr diff <N>
```

変更ファイルから依存の種類を判定する．

| 種類 | 手がかり | 影響先 |
|---|---|---|
| Helm chart | `k8s/apps/*/Chart.yaml`，`Chart.lock` | ArgoCD sync (本番) |
| GitHub Action | `.github/workflows/*` | CI / CD の資格情報 |
| Terraform provider | `terraform/*.tf`，`.terraform.lock.hcl` | `terraform apply` (本番) |
| mise tool | `mise.toml` | 手元と CI のツール版．`helm_version` (`roles/argocd_bootstrap/defaults/main.yml`) との整合に注意 |
| Docker image | `k8s/apps/*/templates/deployment.yaml` の `image:` | ArgoCD sync (本番) |

restic (`ansible/roles/restic_backup/defaults/main.yml`) は Ansible 手動適用．PR 本文の注意書きに従い，merge 後に `backup.yml` を手で適用する手順を案内する．

### 2. 変更点の調査

一次情報のみを使う: 公式リリースノート，CHANGELOG，upgrade guide / migration guide，公式 GitHub の Issue / Discussion．Zenn / Qiita / 学習教材系サイトは使わない．十分な根拠がなければ「一次情報が見つからない」と明記する．

PR 本文に Release Notes が含まれていても，breaking changes の記述は原典で確認する．

確認する観点:
- breaking changes (values のキー名変更・削除，既定値の変更，CRD 変更，必須 Kubernetes / Helm 版の引き上げ)
- この repo の `values.yaml` / 設定で実際に使っている項目への影響 (使っていない項目の変更は無視してよい)
- データ移行・不可逆操作の有無 (PVC，スキーマ，state の変更)

### 3. ローカル検証

PR ブランチを worktree などで取得して実行する (作業ツリーが汚れている場合は先にユーザーへ確認する)．

**Helm chart** (`<app>` = `k8s/apps/` 配下のディレクトリ名):

```sh
helm dependency update k8s/apps/<app>
helm lint k8s/apps/<app>
helm template <app> k8s/apps/<app> --namespace <app> > new.yaml
```

旧版 (main) の `helm template` 出力との diff も取り，Deployment / StatefulSet / PVC / CRD / selector / label の変化を確認する．immutable フィールド (StatefulSet の volumeClaimTemplates，Deployment の selector) の変更は sync 失敗や再作成を招くため要警告．
- umbrella chart の子 chart 既定値は `null` で消せない．`helm template` が通っても sync で拒否されうる (PR #619 / #620)．
- 出力は scratchpad に置き，repo 内に残さない．

**Terraform** (`terraform/`):

```sh
terraform fmt -check -recursive
tflint
terraform init && terraform validate
terraform plan -input=false
```

plan の差分 (destroy / replace) を必ず読む．plan に HCP Terraform の token が必要．使えない場合は CI の `terraform-plan` 結果で代替し，その旨を報告する．

**Ansible** (`ansible/` で実行．`.vault_pass` が必要):

```sh
ansible-playbook playbooks/<name>.yml --syntax-check
```

`--check --diff` は tailnet 接続が要るため，ユーザーに実行を依頼する．

**GitHub Action**: 変更後の入力名・出力名・権限 (`permissions`) の変更を workflow 側の利用箇所と突き合わせる．digest pin (`helpers:pinGitHubActionDigests`) が維持されているか確認する．Actions は deploy 資格情報で動くため，新版の権限要求の増加は要警告．

CI の結果も確認する (`gh pr checks <N>`)．Required check は job 名に pin されている (`terraform-plan` / `ansible-plan` など)．

### 4. 修正コミット (必要な場合のみ)

values や設定の追従が必要な場合は，Renovate ブランチ上で修正する．

- Conventional Commits `<type>(<scope>): <subject>` (英語・命令形・末尾ピリオドなし)．1 コミット 1 変更．本文に Why を書く．
- 該当ディレクトリの `README.md` (日本語，`，` `．` 使用，半角括弧) と，影響があれば `docs/DEPLOYMENT.md` / `docs/RESOURCE.md` を同じ PR で更新する．
- **`git push` の前に必ずユーザーへ確認する**．Renovate は自分のブランチへの他者のコミットを検知すると rebase を止める点も伝える．
- 修正が大きい場合は，Renovate ブランチではなく別 PR に分けることを提案する．

### 5. 判定レポート (日本語)

次の形式で報告する．

- **判定**: merge 可 / 要修正 / 見送り
- **対象**: PR 番号，依存名，旧 → 新バージョン，種類
- **breaking changes と本 repo への影響**: 根拠 (一次情報の URL) 付き
- **検証結果**: 実行したコマンドと結果．実行できなかったものは明記
- **本番への影響**: merge 後に何が起きるか (ArgoCD sync，terraform apply，手動適用が必要か)
- **merge 後の確認手順**: 例えば ArgoCD の sync 状態，Pod の Ready，Grafana の dashboard / alert，Better Stack の heartbeat
- **ロールバック手順**: revert PR で足りるか，データ・state の巻き戻しが要るか
- **採った前提**

## ガードレール

- merge / close / ラベル変更 / PR コメントなど対外的な操作は，ユーザーの確認後に行う．GitHub CLI でコメントや Issue 起票をする場合は「Generated by Claude Code」を文中に入れる．
- 課金が発生する外部 API 呼び出しは，事前に見込み額を示して承認を得る．
- 新しい依存パッケージの追加は承認制．major 更新の過程で代替パッケージを提案する場合も同様で，メンテ状況 (最終リリース日・最終コミット) を併記する．
- SSH / GPG のエラーが出たら停止してユーザーに伝える．
- 関連メモリ (`MEMORY.md` 索引) を確認し，既知の落とし穴 (token 権限，Access の Passkey，HSTS，umbrella chart の null など) に該当しないか照合する．
- 作業で得た再利用可能な知見 (特定 chart の major 更新で必要だった values 変更など) は，PR 番号と日付を添えてプロジェクトメモリに残す．
